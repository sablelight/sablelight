Double-checked locking, and the test that caught me

A cached HTTP client that only rebuilds when the proxy actually changes — and the test I wrote wrong to prove it worked.

The extracted proxyhttp package keeps a shared *http.Client whose transport respects a proxy setting that can change while the process is running. Rebuilding an http.Client is cheap in isolation. Doing it per request is not: you throw away the connection pool and force a fresh TLS handshake against every origin.

So the client is cached, and only rebuilt when the effective proxy URL changes.

func Client() *http.Client {
    current := ProxyURL()

    clientMu.RLock()
    if sharedClient != nil && cachedProxyURL == current {
        clientMu.RUnlock()
    return sharedClient
    }
    clientMu.RUnlock()

    clientMu.Lock()
    defer clientMu.Unlock()

    // re-check: another goroutine may have rebuilt while we waited
    if sharedClient != nil && cachedProxyURL == current {
        return sharedClient
    }

    sharedClient = &http.Client{ /* ... */ }
    cachedProxyURL = current
    return sharedClient
}

The bug was in my test

I wrote this to prove the client rebuilds when the proxy changes: 

t.Setenv("PROXYHTTP_MODE", "direct")
direct := Client()

t.Setenv("PROXYHTTP_URL", "socks5://127.0.0.1:9050")
proxied := Client()

if direct == proxied {
    t.Error("Client() did not rebuild after the proxy URL changed")
}

It failed. Every time.

The mode was direct. In that mode ProxyURL() ignores PROXYHTTP_URL entirely and returns "". So the effective proxy never changed, the cache key never changed, and no rebuild happened — which was the correct behaviour.

The cache is keyed on the effective proxy, not on raw config. That is the whole point. Changing a setting that cannot affect the route should not discard a warm connection pool.

What I actually wanted to pin

Fixing the test meant writing the test I should have written:

func TestClientIgnoresIrrelevantConfigChange(t *testing.T) {
    Invalidate()
    t.Setenv("PROXYHTTP_MODE", "direct")
    t.Setenv("PROXYHTTP_URL", "")

    before := Client()

    // in "direct" mode this cannot affect the route, so no rebuild
    t.Setenv("PROXYHTTP_URL", "socks5://127.0.0.1:9050")
    if after := Client(); after != before {
        t.Error("Client() rebuilt for a config change that cannot affect the route")
    }
}

A failing test is not always the code telling you something. Sometimes it is the code telling you it is right and your model of it was wrong. Both happen, and the honest move is to work out which one you are looking at before changing either.

Coverage on both packages ended up at 92%. More usefully, the race detector passes on a test that hammers Client() from 32 goroutines and asserts they all got the same pointer back — which is the property the double-check exists to provide.
